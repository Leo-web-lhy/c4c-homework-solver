## 阶段 1｜环境盘点与路线判定

- **任务**：判断这台机器能否按要求产出排版作业，避免选到跑不通的路线。
- **与 AI 的协作方式**：AI 逐个探测依赖，得到的关键事实：
  - Python 3.12.13；可用 `pypdf / pdfplumber / python-docx / matplotlib / latex2mathml`；
  - **无** `pdflatex / xelatex / lualatex / latexmk / tectonic / pandoc` → LaTeX 编译路线不可行；
  - **无** `reportlab / fpdf / fitz` → 不能靠 Python 库直出 PDF；
  - 本地大模型端口（11434/1234 等）全部不通，Moonshot `/v1/models` 返回 401、DashScope 根路径 404 → **无可用 LLM 基线**。
- **路线决策**：排版改为 **HTML + MathML + Edge headless 打印 PDF**。为验证这条路能出中文，先写一个最小验证脚本：`EDGE_RC 0 / SEC 32.4 / PDF_BYTES 72188 / PAGES 1 / TEXTCHARS 290 / HAS_CN True` —— 中文可渲染，路线成立。
- **产出物**：`.scratch\edge_pdf_test.py`、环境盘点结论（写入方案设计 §1）。
- **人工介入**：无。

## 阶段 3｜求解内核：从"照抄模板"到"独立校验"

- **任务**：让非微积分方向的题真能被解出来，且答案可验证。
- **与 AI 的协作方式**：starter 的 `solve.py`（67 KB）走的是"分类 → 模板"路线，对线性代数/ODE 没有覆盖。AI 另建 `scripts\solve_kernel.py`（约 21.7 KB，**纯 ASCII 源码**，中文文案外置到 `domain_skills\la_ode_templates.json`，避免本机中文控制台崩溃），实现 6 个求解器：

  | 求解器 | 覆盖 |
  |---|---|
  | `la_matrix_form` | 矩阵求逆 |
  | `la_eigen` | 特征值 / 特征向量 |
  | `la_solve_linear_system` | 线性方程组 |
  | `ode_separable` | 可分离变量 |
  | `ode_linear_first` | 一阶线性（积分因子） |
  | `ode_second_order_cc` | 二阶常系数 |

  每个求解器配套一个**独立**校验通道（`A·A⁻¹=I`、`A·v=λ·v`、解回代残差、`.doit()` 后 `simplify(残差)==0`），校验结果写回布尔 `meta.verify_ok`。
- **产出物**：`scripts\solve_kernel.py`、`domain_skills\linear_algebra_ode.yaml`、`domain_skills\la_ode_templates.json`、`scripts\run_domain.py`。
- **人工介入**：无。

## 阶段 4｜六轮真机调试：每个 bug 都留了证据

- **任务**：把 0/0 的求解结果推到可用。
- **与 AI 的协作方式**：AI 每轮都重新跑一遍并把计数打出来，据此定位：

  | 轮次 | 现象 | 根因 | 修法 |
  |---|---|---|---|
  | 1 | `sympify` 报 `SympifyError` | 隐式乘法 `2x` | 归一化为 `2*x` |
  | 2 | 同一报错 | 题面前缀叙述整句进 SymPy | 剥掉题号与冒号前叙述，保护 `det/rank/inverse` |
  | 3 | 解析失败 | 中文句号 `。` 留在方程尾 | `rstrip` 字符集加入 `。；、` |
  | 4 | **正确解被判错** | `subs()` 后 `Derivative` 未求值，残差 ≠ 0 | 先 `.doit()` 再 `simplify()`；人工残差 `MANUAL_RESIDUAL=0` 确认 |
  | 5 | 校验计数恒为 0 | 用中文文案前缀匹配"校验通过"，两条文案共享前缀 | 改为只认 `meta.verify_ok` 布尔 |
  | 6 | **PDF 是空白的** | 见阶段 5 | 见阶段 5 |

  第 4 轮是典型的"AI 自己判自己"翻车：oracle 写错时，它会稳定地把对的答案判成错的。定下规矩——**校验器与被校验对象必须独立，且计数不得从本地化文案推断**。
- **产出物**：`output\3_solutions.json`，最终 `total=7 solved=6 unsolved=1 verify_ok=6 verify_fail=0`。
- **人工介入**：无。

## 阶段 5｜最有价值的一次翻车：空白 PDF

- **任务**：把 7 题答案排成 PDF。
- **与 AI 的协作方式**：第一版渲染器返回 `ok=True rc=0 1.2s 15927B` —— 从退出码和文件体积看"成功"。AI 额外用 `pypdf` 抽正文复核，得到 `PAGES 1 / TEXTCHARS 20 / HAS_CN False`：**只有标题，正文全空**。
  - 根因：渲染器只认 `meta["sets"]` 分组结构，而本流水线的 payload 是 `id/text` 平铺结构 → 分组列表为空 → 正文为空。
  - 修复：增加默认单分组、`id→problem_id` 与 `text→problem_text` 回退映射、空 `steps` 不打印标题、裸 LaTeX 自动包 `$$…$$` 走 MathML。
  - 修复后：`PAGES 2 / TEXTCHARS 925 / HAS_CN True`，PDF 240,718 B。
  - **加装回归门**：新增 `pdf_text_check()`，正文 < 200 字符或中文字数 = 0 即判 `FAIL` 并返回退出码 **7**，让"空白 PDF"再也不能冒充成功。该轮实跑输出 `[pdf-check] OK pages=2 chars=925 cjk=288`；返修轮补齐推导后同一门给出 `[pdf-check] OK pages=6 chars=4163 cjk=1383`。
- **产出物**：`scripts\render_html_pdf.py`（13,547 字符）、`output\homework.html`、`output\homework.pdf`、`2023108610260_C4C_output.pdf`。
- **人工介入**：无。
