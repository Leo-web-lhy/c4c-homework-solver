## 2. 卡点与突破

### 卡点 1（最有价值）：渲染器吐出空白 PDF，而所有信号都说"成功"

现象：流水线返回 `rc=0`，`output/homework.pdf` 生成且 15,927 B > 1KB，日志里 `[pdf] ok=True`。但人工打开是空白页。核验后确认：1 页、正文抽取 **20 字符**、中文字数 **0**。

根因：`build_html` 只认 `meta["sets"]` 结构，而本流水线 payload 用的是 `id/text` 结构 → 正文分组为空 → 只渲染出空壳，但异常路径没有被触发，所以 `ok=True` 照旧。

突破：加默认分组 + `id→problem_id`、`text→problem_text` 字段映射 + 空 `steps` 时不打印小标题 + 答案走 `$$…$$` MathML。

**由此得到的教训（已固化为代码）**：`rc=0` 且文件大于 1KB **完全不足以证明产出有效**。新增回归门 `pdf_text_check()`：用 `pypdf` 抽正文，字符数 < 200 或中文字数 = 0 即判 FAIL、退出码 7。修复后 `[pdf-check] OK pages=2 chars=925 cjk=288`，PDF 240,718 B。

### 卡点 2：残差 oracle 把正确解判成错误

第 6 题 `y''-y'-6y=0, y(0)=1, y'(0)=0`，理论解 `(2e^{5x}+3)e^{-2x}/5` 是正确的（`C₁+C₂=1`、`3C₁-2C₂=0` → 2/5、3/5）。但 `subs()` 后代数式里导数项仍是未求值的 `Derivative` 对象，`simplify(残差)` 于是不为 0 → **假阴性**。

修法：先 `.doit()` 求值再 `simplify()`；并用人工残差复算 `MANUAL_RESIDUAL=0` 做交叉确认。修完全部 6 题 `verify_fail=0`。

### 卡点 3：校验计数恒为 0

初版按中文文案前缀匹配来统计"校验通过"，但「校验通过」和「校验未通过」共享同一前缀 → 永远失配，计数恒 0，看起来像"一题都没校验"。

修法：计数只认结构化字段 `meta.verify_ok`（布尔），**禁止从本地化文本反推状态**。这是本地化文本当数据源的通病，不只是这一处。

### 卡点 4：输入解析的三种脏数据

| 脏数据 | 表现 | 修法 |
|---|---|---|
| 隐式乘法 `2x` | 直接进 SymPy → `SympifyError` | `_norm_math()` 补成 `2*x` |
| 叙述文字 `Solve the linear system: …` | 整句进 SymPy 报错 | `_strip_label()` 剥题号与冒号前叙述，同时保护 `det/rank/inverse` 等函数名 |
| 句末中文标点 `= 8。` | 解析失败 | `rstrip` 字符集加入 `。；、` |

## 3. 根因归类

1. **成功信号不可信**：`rc=0`、文件非空、`ok=True` 三者都不是内容证据。凡是"生成型"步骤都必须配内容级断言。
2. **本地化文本当数据源**：中文文案既是给人看的，又被拿来当判断依据，一次共享前缀就废掉整条统计。
3. **oracle 与被测对象共用假设**：残差校验依赖 SymPy 的求值时机，和求解器共用同一套符号假设，所以正确解也能被判错。校验通道要尽量换一条独立路径。
4. **环境即约束**：无 LaTeX、无 LLM key、无 GPU。这些不是"以后补"，是需要在交付物里**显式声明边界**的东西。

## 5. 与 AI 的协作方式（如实记录）

- 分工：AI 承担"写内核 → 跑 → 读输出 → 定位 → 改"的循环，人承担"看结果对不对"的判断。本次 6 个缺陷中，**卡点 1（空白 PDF）是人眼发现的**，不是自动检测发现的——这恰好说明当时的自检体系存在盲区，也是后来补 `pdf_text_check()` 的直接原因。
- 有效的做法：把每次失败的**真实报错原文**喂回去再改，而不是笼统描述"报错了"。三种输入脏数据（隐式乘法、叙述文字、中文标点）就是这样逐个暴露出来的。
- 无效的做法：相信"跑通了"这个结论。本轮前 5 轮都属于"跑通了但没对"。
- 未留存项：逐字 Prompt 原文未单独存档，此处如实标注，不臆造。

## 6. 一句话总结

这次真正的产出不是 6/7 的求解率，而是**一条把"假成功"挡在门外的回归门**：从"退出码 0 就算过"改成"能抽出 200 字符以上正文、含中文字符才算过"。求解率可以再提，但自检的判据错了，提上去的数字也不可信。
