## 3. 独立校验机制（不是"能跑就算过"）

每类题都有与求解器**相互独立**的校验通道，校验结果写回结构化的 `meta.verify_ok`（布尔），不依赖中文文案：

- 矩阵求逆 → `A·A⁻¹` 与单位矩阵逐元素比对
- 特征对 → `A·v` 与 `λ·v` 逐分量比对
- 线性方程组 → 解回代每行残差为 0
- ODE → 把解代回原方程，`.doit()` 求值后 `simplify(残差)` 必须恒为 0

## 4. 本轮真实发现并修复的 6 个缺陷

| # | 缺陷 | 表现 | 修法 |
|---|---|---|---|
| 1 | 隐式乘法未归一化 | `2x` 直接进 SymPy → `SympifyError` | `_norm_math()` 把 `2x` 补成 `2*x` |
| 2 | 题目带叙述文字 | `Solve the linear system: ...` 整句进 SymPy 报错 | `_strip_label()` 剥题号与冒号前叙述，保护 `det/rank/inverse` 等函数名 |
| 3 | 中文句号留在方程尾 | `... = 8。` 解析失败 | `rstrip` 字符集加入 `。；、` |
| 4 | 残差 oracle 假阴性 | `subs()` 后导数项仍是 `Derivative` 未求值 → 残差 ≠ 0，**正确解被判错** | 先 `.doit()` 再 `simplify()`；人工残差复算 `MANUAL_RESIDUAL=0` 确认 |
| 5 | 校验计数恒为 0 | 「校验通过」「校验未通过」共享中文前缀 → 按文案前缀匹配永远失配 | 计数只认 `meta.verify_ok` 布尔，禁止从本地化文本推断 |
| 6 | **渲染器吐出空白 PDF** | `build_html` 只认 `meta["sets"]`，而本流水线 payload 用 `id/text` 结构 → 正文为空，PDF 仍 `ok=True`、15,927 B、1 页、20 字符、0 个中文字 | 增加默认分组 + `id→problem_id`／`text→problem_text` 映射 + 空 `steps` 不打印标题 + 答案包 `$$…$$` 走 MathML |

第 6 条是本轮最有价值的发现：**`rc=0` + 文件大于 1KB 完全不足以证明 PDF 有内容**。修复后新增回归门 `pdf_text_check()`：用 `pypdf` 抽取正文，字符数 < 200 或中文字数 = 0 即判 `FAIL` 并返回退出码 7，不再静默"成功"。

## 6. 未覆盖与已知边界（不粉饰）

1. **无 LLM 对照基线**：本机 `DASHSCOPE_API_KEY` / `MOONSHOT_API_KEY` / `DEEPSEEK_API_KEY` / `OPENAI_API_KEY` 均未配置（Moonshot `/v1/models` 返回 401，DashScope 根路径 404）。因此挑战建议的「与通用大模型输出对比」一项**未做**，替代方案是人工手算逐题复核（§2 最后一列）。这是明确缺口，不写成"已完成"。
2. **无 LaTeX 工具链**：`pdflatex/xelatex/lualatex/latexmk/tectonic/pandoc` 全部不可用，PDF 走 HTML + MathML + Edge headless；因此原 `homework.tex` 路线保留但不作为主交付路径。
3. **概念题留白**：第 7 题不做自动求解，也不让模型去"猜"，输出中标注为未求解并说明原因。
4. **PDF 文本抽取**：MathML 公式在 `pypdf` 抽取中部分呈现为字符片段，`chars=925` 是文本层可抽取量，不代表视觉完整度；视觉正确性由 2 页排版与中文字数共同佐证。
5. **可复现范围**：仅在本机 Windows + Python 3.12.13 实跑过，未在 Linux/macOS 验证，未做 CI。
